# Teahouse Tibetan — Agent Notes

## Development workflow

- Active development and testing target: **Chrome**.
- Do **not** run a full production build (`npm run build`) after every change.
- To test manually, run `npm run build` for a one-time `dist/chrome/` build or `npm run dev` for dev-mode builds.
- Production builds for Edge, Firefox, and store zips are done only when the extension is ready to launch.
- **Commit after every feature change or addition** — one focused commit per feature/fix, rather than batching unrelated work.

## Linting

- ESLint 9 (flat config in `eslint.config.js`) lints `src/` and `tools/`; run it with `npm run lint`.
- Vendored bundles `src/shared/jsewts.js` and `src/shared/ewts-converter.js` are ignored.
- The pre-commit hook runs `npm run lint` first and aborts the commit on any error. Fix lint errors rather than bypassing the hook with `--no-verify`.

## Versioning

- The patch version is auto-incremented on every commit by `tools/bump-version.js`.
- The local pre-commit hook (`.git/hooks/pre-commit`) runs lint, then the bump, and stages `package.json`, `package-lock.json`, and `manifest.json`.
- Do not manually edit version strings; let the hook handle it to avoid double-bumps.

## Build notes

- `public/data/...` paths in the source `manifest.json` are flattened to `data/...` in `dist/` by the `extension` build tool.
- `dist/` is gitignored and generated by `npx extension build`.
- Extension pages beyond the popup and options (the dictionary, "My words" and first-run welcome pages) live in top-level `pages/`; the build compiles every HTML file there to `dist/<browser>/pages/`. Open them with `chrome.runtime.getURL("pages/<name>.html")` and add each one to the page list in `tools/test.js`.
- `src/background/service-worker.js` opens `pages/welcome.html` on first install only. The welcome page loads the content-script files directly so its sample text is annotated (content scripts don't run on extension pages).
- Elements marked `data-teahouse-skip` are never annotated.
- Saved words are stored in `chrome.storage.local` under `savedWords` (see `src/shared/wordList.js`); settings stay in `chrome.storage.sync`.

## Websites

- `site/` holds two static brochure sites: `teahouselanguages.com/` (umbrella) and `tibetan.teahouselanguages.com/` (one subdomain per language). There's no build step. Setup for hosting (Cloudflare Pages), email (Cloudflare Email Routing) and the Google Forms is in `site/README.md`.
- `style.css` and `icon.png` are duplicated in each site folder; keep the copies identical.
- The Chrome Web Store privacy policy URL is `https://tibetan.teahouselanguages.com/privacy.html`; update that page when the extension's data handling changes.
